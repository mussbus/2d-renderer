=====================================================================
3. HARDEN THE VALIDATOR BEFORE MODIFYING ART
=====================================================================

Before attempting to make production pass, audit the Prompt-25C validator
itself.

Several parts of the current implementation are intentionally broad first-pass
contracts and MUST NOT be treated blindly as immutable truth.

Specifically inspect:

A. GENERIC ANATOMY LANDMARKS

`anatomyGeometry(role, view)` currently uses role/view templates.

Verify every landmark against the actual visible production pixels.

Male and female art must not be forced to use an inaccurate shared landmark
simply because both are feet, torsos, hands, etc.

Where the real art requires it, support data-driven geometry by:

    style
    + view
    + semantic region

rather than only:

    role
    + view.

The landmark must describe the actual semantic point visible in the art.

Examples:

- actual ankle;
- actual heel;
- actual toe tip;
- actual sole endpoints;
- actual shoulder interface;
- actual elbow;
- actual wrist;
- actual hip;
- actual knee.

B. GENERIC EQUIPMENT LANDMARKS

Verify attachmentGeometry against actual production pixels.

Do not assume that a semantic point sits at a generic percentage of every
source region if the artwork says otherwise.

C. FIT CONTRACT DEFAULTS

The current FitContract defaults are useful baseline values but they MUST NOT
silently define the design of every garment.

Different garments have different intended geometry.

Examples:

A halter top is not supposed to cover the same torso area as a cardigan.

A miniskirt is not supposed to cover the same pelvis/thigh region as pants.

A strappy shoe is not supposed to cover the same visible alpha area as a boot.

A puff sleeve may intentionally extend substantially beyond the arm silhouette.

A wide-brim hat must intentionally extend far outside the head alpha.

Therefore create explicit DATA-DRIVEN fit contracts where required.

Do NOT merely loosen all global defaults.

D. COVERAGE SEMANTICS

Do not interpret:

    minimum_coverage = 0.90

as:

    garment must overlap 90% of every visible anatomy pixel

unless that is genuinely the design contract.

Coverage must refer to the garment's INTENDED TARGET REGION.

Add/extend bounded coverage-zone metadata if necessary.

Examples:

shoe:
    sole/heel/toe/enclosure fit region

halter top:
    intended chest/torso region

shorts:
    waist/pelvis and declared upper-thigh region

glove:
    intended hand/wrist region

sleeve:
    intended arm span

The validator must reject incorrect fit WITHOUT forcing every garment to become
a full-coverage garment.

E. MULTIPLE/LAYERED COMPONENTS

The current audit frequently resolves the first record matching a role.

That is insufficient for layered wardrobes.

Every submitted equipment visual that declares a fit contract must be validated
independently using:

- actual semantic component identity;
- actual bound anatomy identity;
- actual side;
- actual view.

Do not validate only the first torso garment, sleeve, lower garment, etc.

Layered outfits must validate every applicable component.

F. MALE + FEMALE DEBUG EVIDENCE

The debug geometry route must be capable of showing relevant geometry for both
production characters, not only the female character.

sprite currently happens to be.

    valid ratio 0.96..1.08
to
    valid ratio 0.60..1.40

unless there is a legitimate authored garment-design reason and that reason is
represented as a specific semantic fit contract.

Any modification to:

- landmark position;
- fit range;

- orientation tolerance;
- gap/overlap tolerance;
- proportion range;

must have an explicit engineering justification.

For each such change report:

    previous contract
    new contract
    why previous contract was semantically wrong
    evidence from visible pixels/design intent
    controlled fixture proving the corrected validator still rejects bad data

The validator is the ruler.

Do not shorten the ruler because the object is wrong.

7. FOOTWEAR — MUST BE FULLY CORRECT
=====================================================================

The current footwear is visibly wrong.

This is a hard acceptance area.

For EACH semantic shoe, EACH required view, and representative poses:

The shoe must:

- bind to the correct semantic foot;
- point in the same forward direction as that foot;
- have heel aligned to heel;
- have toe aligned to toe;
- have sole axis aligned to the foot's sole axis;
- have an appropriate length relative to the foot;
- have an appropriate width;
- cover/enclose the declared footwear-fit region;
- not incorrectly cover the opposite foot;
- not pile toward character center;
- not require global skeleton distortion to appear correct.

A shoe whose sprite is facing the opposite direction from the foot is an
automatic failure.

A shoe whose sole has visibly different rotation from the foot is an automatic
failure.

Do NOT fix a backwards source shoe by rotating the actual foot.

Correct:

- source orientation;
- mirrored orientation;
- authored pivot;
- appropriate view-specific rest rotation;
- or local equipment transform,

whichever is actually wrong.

Front and side artwork may require distinct semantic geometry.
